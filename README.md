# AI Thesis Polisher

本项目是一个在 Windows 本地运行的论文润色工具。

它会读取 `.docx` 文档，调用兼容 OpenAI 接口的大模型 API 生成修改建议，再通过 Microsoft Word 的原生修订功能把修改写回文档。结果不是纯文本覆盖，而是保留 Track Changes，方便作者逐条审阅。

项目当前使用 Streamlit 作为界面层，Word 操作依赖 `pywin32` / `win32com`。

## 适用场景

- 需要保留 Word 修订痕迹，而不是拿一份“改完但看不出改了什么”的新文档
- 论文篇幅较长，希望按段落处理，降低一次性大段投喂带来的误改
- 需要生成 Excel 报表，回看每条建议对应的句子、原因、状态和优先级

## 当前处理流程

### Stage 0

先按章节读取全文，生成章节工作笔记。笔记会概括本章研究内容、关键术语、容易误判的专业表达和文风风险区域。

### Stage 1

对每个段落按句标注后逐句审阅，提名可能需要修改的短语。Prompt 会带上：

- 章节笔记
- 前后文
- 不应修改的内容约束
- 被动句处理边界

### Stage 2

对 Stage 1 的提名结果做保守复审，过滤掉：

- 没有实质提升的改写
- 误伤专业术语、缩写、数值、引用的改写
- 不该动的合理被动句
- 破坏逻辑衔接的改写

### 输出

- Word：原文档写入修订痕迹
- Excel：按章节分 Sheet 输出审核明细

Excel 中会包含：

- 段落号
- 句子编号
- 原句
- 润色理由
- 修改前片段
- 修改后片段
- 润色后完整句
- 状态
- 优先级

## 这版新增内容

- 章节级 Stage 0 预读，不再让每段都在无全局上下文的情况下单独判断
- 更严格的 Stage 2 复审规则
- 中文 Prompt 增加被动句“该改 / 不该改”示例
- Excel 按章节分 Sheet
- 支持删除型修改写入 Word 修订
- 支持在界面中设置输出目录
- 每次运行自动把 Word 和 Excel 落盘到指定目录
- 支持对 Stage 0 / Stage 1 / Stage 2 追加自定义 Prompt 说明

## 使用说明

### 1. 配置模型

在左侧栏填写：

- `API Key`
- `Base URL`
- `Model`

支持兼容 OpenAI Chat Completions 的接口。

### 2. 设置输出目录

左侧栏可以设置“输出根目录”。

每次运行时，程序会在该目录下自动创建一个新的时间戳子目录，并把结果写进去，例如：

```text
outputs/
  20260324_201530_demo_paper/
    Polished_demo_paper.docx
    Report_demo_paper.xlsx
```

页面刷新后，如果上一次输出文件仍然存在，界面会尝试恢复最近一次结果的下载入口。

### 3. 上传文档并运行

上传 `.docx` 后，可以设置：

- 语言模式
- 润色强度
- 最小段落长度
- 是否开启交叉复审
- 需要跳过的章节

### 4. Prompt 自定义

界面里提供三个可选输入框：

- Stage 0 章节理解附加要求
- Stage 1 提名附加要求
- Stage 2 复审附加要求

这些内容会追加到内置 Prompt 末尾，而不是直接替换整个 Prompt。

这样做的目的很简单：

- 保留当前流程里已经验证过的基础约束
- 允许用户增加自己的规则
- 降低因为完全自定义 Prompt 导致格式输出失控的概率

## 已知限制

### 结构化章节记忆（默认）

章节理解只选择原句编号和原文术语，程序补齐完整引文及段落位置，不让模型自由编写事实摘要。编辑和复审只接收当前章节内的相关记忆，相邻段落也不会跨章节混入。

输出新增 `ChapterMemory.json`，包含出处、保护状态、预算覆盖信息及被丢弃的选择。Prompt 高级设置可填写明确保护术语。记忆预算不足会明确标记。

无法在原文中验证的单条选择会被丢弃并记录，该章节其余记忆照常使用；只有当模型给出的选择**全部**无法验证时才判该章节失败。被丢弃的条目不会进入记忆、不会出现在编辑或复审的 Prompt 里，也不会被"修复"成合法内容。缓存中的记忆仍按严格校验，不退回自由文本或冒充无需修改。

出处验证不等于科学事实或语义已经验证。范围、缓存行为和真实 API 对比见 [章节记忆验证记录](benchmarks/MEMORY_VALIDATION.md)；失败半径的改动与实测边界见 [记忆失败半径记录](benchmarks/MEMORY_SALVAGE.md)。

### 分阶段模型与独立复审

左侧可选择不复审、同模型复审或独立模型／接口复审。开启“分阶段模型配置”后，章节理解、编辑、复审分别设置模型、接口、温度、超时和尝试次数。默认仍为同模型复审，不自动增加模型或切换供应商。

同模型复审沿用编辑阶段的模型及凭据；独立复审必须指定不同模型或接口。不同地址不自动继承主 Key，阶段 Key 仅留在本次会话。新远程地址默认要求 HTTPS；已有 HTTP 主接口保留明确标注的兼容行为，新 HTTP 地址需主动开启。

每次输出增加 `Run.json`，记录实际路由、调用次数、耗时和可用的 token 用量（不含 Key 字段）。模型和参数变化会使相关缓存失效，章节理解缓存不因仅更换复审模型而失效。

固定样本对比没有证明跨模型必然更好，详见 [复审评测与边界](benchmarks/REVIEW_VALIDATION.md)。

### 编辑调用打包（默认关闭）

界面可设置"每次编辑调用打包的段落数"。同一章节的连续段落会合并为一次编辑调用，避免每段都重复发送邻居段与章节记忆。默认值 1，即与之前完全一致。

打包只改变"怎么问"，不改变"怎么写"：复审也按同一批次合并请求，但决策按段拆回，写回仍是每段一个独立原子事务，缓存仍按段命中。整批失败（格式、超时、HTTP）会自动退回逐段调用，绝不记成"无需修改"；批次不跨章节，不包含已有缓存的段落。

短语料（每章 6 段）打包到 6：调用数 21→7、token 25.4k→17.5k、正文重复倍率 3.31→0.99，段落级未出现漏检或误改。

18 段单章语料（批次外仍有邻居、按句统计）：调用数 27→8、token 35.3k→26.5k、倍率 3.76→1.30，但**存在真实的质量差异**——每次运行命中的语病句从 13.71 降到 13.36（−2.6%），未标注句上的改动从 0.14 升到 0.55。具体是：主谓不一致抓得更稳，冗长句更容易漏，时态过度矫正更频繁。不涉及事实、数字、引用和情态词。

因此默认值保持 1：省 70% 调用换一点点召回，这个取舍该由你按文档决定，不该由工具替你决定。改动该值会使已有建议缓存失效。测量与边界见 [打包实测记录](benchmarks/PACKING.md)。

### 批量候选筛选（已实测，未启用）

先用一个筛选模型判断哪些句子值得改、只把候选句送编辑，这条路走过实测，**没有通过验收，因此没有实现跳过模式**。

引擎里保留 `triage_mode=shadow`：筛选照常调用但**不跳过任何句子**，判定记入 `Run.json`，事后与实际写入的修改逐句对照。默认 `off`。

实测（12 段 / 32 句 / 打包 6 段）：Qwen3-30B 筛选 5 次运行漏掉 45 处修改中的 7 处（15.6%），DeepSeek V4 Flash 3 次运行漏掉 29 处中的 1 处（3.4%）。筛选本身每次运行花掉 3,990–5,279 token，而它能省下的编辑输出估计也就 4,000–4,500——**筛选必须读一遍和编辑一样的原文，省不了输入 token**；打包之后也不剩什么调用数可省。

用"每处真实修改有 3.4%–15.6% 概率被丢掉"换约等于零的开销，不划算。数据与边界见 [筛选实测记录](benchmarks/TRIAGE.md)。

### P1 句子定位与安全写回（当前 UI 默认流程）

- 模型按句子 ID 返回完整修订句或 KEEP，不再生成待查找的 `old` 片段。
- 原文位置不清洗，显式转换为 Word UTF-16 Range；重复句按位置区分。
- 程序生成局部差异、倒序写入；每段为一个撤销事务，写后验证最终文本。
- 中途写入或核验失败会撤销整组；无法确认回滚则中止且不保存该运行的 Word。
- 已有修订、表格或复杂结构会保守跳过/拒绝，并在报告中给出原因；不会自动接受你的已有修订。
- Excel 的结果句显示实际写入结果，而不是把被拒绝的建议显示为已完成。

完整范围、限制和验证记录见 [P1 验证记录](benchmarks/P1_VALIDATION.md)。以下 P0 能力继续保留。

### P0 可靠性与校验

- 上传身份由内容 SHA-256 与文件名共同识别，换文件时重新解析章节。
- 每次运行复制原始上传文档到独立输出目录，不继续修改上传缓存。
- 段落缓存包含文档/段落内容、模型端点和相关配置；旧版 `done` 缓存因版本变更失效，保留原文件但不复用。
- 缓存仅保存模型建议；重新运行时重新校验、写入新 Word 并重建完整报告。中断后的恢复方式是从原始上传重新运行，复用已保存建议；不是原地续写半成品。
- Excel 明确区分 `MODEL_FORMAT_ERROR`、`MODEL_TIMEOUT`、`MODEL_HTTP_ERROR`、`VALIDATION_REJECTED`、`PATCH_FAILED` 和无修改；有失败时界面不会宣称全部成功。
- 写回前保守检查数字、常见单位、引用、缩写和部分化学式的内容、数量与顺序。引擎配置 `protected_terms` 可追加精确术语；重复片段不冒险定位。
- 规则不是语义事实校验器，不能保证技术事实零误伤。缓存默认本地保存论文文本/建议，不适合多进程并发运行。

离线评测说明见 [benchmarks/README.md](benchmarks/README.md)。包含 16 条合成样本和 20 条开放论文派生案例（10 条原句及对应构造错误），来源及 CC BY 4.0 许可见 [benchmarks/SOURCES.md](benchmarks/SOURCES.md)。标签由 Agent 制定，不冒充人工接受率；并非真实论文自然错误的代表性质量评测。

本次真实 API、缓存恢复和 Word 验证结果见 [P0 验证记录](benchmarks/VALIDATION.md)。
